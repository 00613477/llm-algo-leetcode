## Extension Blueprint | 扩展项目蓝图

### 33. Profiling-Driven End-to-End Optimization | profiling 驱动的端到端优化项目

- **项目目标：** 把 `Part 1` 的 profiling 方法论真正落到一个完整优化闭环里，形成“测量 -> 定位 -> 修改 -> 复测”的工程习惯。
- **建议对象：** 选一个已有的训练或推理流程作为 baseline，可以是 `30-32` 中的某个实验，也可以是更小的合成 workload。
- **重点关注：** 先定位瓶颈来自数据、算子、通信还是显存，再决定改动点，而不是一开始就重构整条链路。
- **预期产出：** 性能热点图、优化前后对比表、瓶颈定位说明、可复现的修改记录。
- **前置来源：** [Part 1 profiling 方法](../01_Hardware_Math_and_Systems/13_Profiling_and_Bottleneck_Analysis.md)、[2.3](./2_3.md)、[2.5](./2_5.md)、[2.6](./2_6.md)

### 34. Distributed Parallel Benchmark | 分布式并行基准项目

- **项目目标：** 把 ZeRO、Pipeline Parallelism 和 Tensor Parallelism 放到同一套 benchmark 里比较，形成并行策略选型依据。
- **建议对象：** 选一个结构足够小、但通信特征明显的模型或子图，避免 benchmark 过大导致调参成本过高。
- **重点关注：** 显存占用、吞吐、延迟、通信量和实现复杂度，分别回答“省了什么”“换来了什么”“代价是什么”。
- **预期产出：** 并行策略对比表、显存 / 吞吐 / 延迟曲线、推荐选型结论、通信与调度观察记录。
- **前置来源：** [2.8 分布式并行策略](./2_8.md)

### 35. Quantized Inference and Deployment | 量化推理与部署项目

- **项目目标：** 把 W8A16、4-bit 量化和 QLoRA 这些压缩策略放进一个可复现的推理 / 部署流程，比较精度、速度和显存之间的权衡。
- **建议对象：** 选一个单机可运行的推理模型或轻量微调模型，优先保证端到端链路能稳定复现。
- **重点关注：** 量化前后显存、延迟、吞吐和精度变化，明确哪些方案适合推理，哪些方案更适合微调。
- **预期产出：** 量化前后对比表、推理指标统计、部署注意事项、推荐的工程实践结论。
- **前置来源：** [2.7 高级推理与压缩优化](./2_7.md)

## 2.7 / 2.8 延伸项目方向 | 2.7 / 2.8 延伸项目方向

这部分用于承接 `36-42` 这些继续向下生长的主线：它们不是替代 `30-35`，而是把推理、量化和并行再拆细一层，变成更贴近 serving、cache、benchmark 和通信剖析的项目候选。

### 推理服务与缓存方向

- **36 Prefix Caching and Chunked Prefill：** 适合做前缀缓存命中率、切块预填充和请求复用的对比实验。
- **37 Multi-Token Decoding：** 适合做多 token 生成、草稿-验证链路和生成效率比较。
- **38 Decode Scheduling：** 适合做 prefill / decode 调度、批次排布和优先级规则比较。
- **41 KV Cache Scheduling：** 适合做 KV cache 管理、调度和复用策略验证。

### 量化与部署方向

- **39 GPTQ and AWQ Weight Quantization：** 适合做权重量化方法、校准策略和误差控制比较。
- **40 FP8 and KV Cache Quantization：** 适合做 FP8 推理和 KV cache 量化的精度 / 性能权衡。

### 通信剖析方向

- **42 Communication Profiling with NCCL：** 适合做多卡通信热点、等待时间和通信与计算重叠分析。
